# Client-only 4K forced-subtitle segment test

The user cannot change the Emby server or provide sidecar SRTs. Prior trials did not solve the issue: full-file HTTP subtitle requests timed out, and native selection produced a checkmark without visible text. This tests a different documented user-authenticated API capability without new credentials or admin actions.

Official Emby reference lists `StartPositionTicks`, `EndPositionTicks` and `CopyTimestamps` for GET `/Videos/{Id}/{MediaSourceId}/Subtitles/{Index}/Stream.{Format}`:
https://dev.emby.media/reference/RestAPI/SubtitleService/getVideosByIdByMediasourceidSubtitlesByIndexStreamByFormat.html

The test requests 60-second SRT intervals around the current content position with copied absolute timestamps. It prefetches 15 seconds before the cached interval ends, retains at most three intervals, and reuses the original player-internal text renderer. The ordinary API key is reused only in requests; it is not written to diagnostics. The guarded Requests wrapper and TLS verification remain. Payload per interval is capped at 1 MiB. Connect/read inactivity timeouts are 5/30 seconds, not a total-duration guarantee. Only 404/405 proceeds to an alternate root. Request/response bounds, status, byte/cue counts and exception class names are logged to `/tmp/embyflow_subtitle_segments.jsonl`, without URLs, tokens, IDs or dialogue text.

Scope: embedded German forced text subtitles in the active 4K MediaSource. HD, external subtitles, other languages and full non-forced tracks retain the preceding downloader. The unsuccessful native path and sidecar-only automatic test are unhooked if installed. The too-short V4 15-second full-file timeout is restored to 120 seconds. Manual off remains authoritative. Closing/changing source cancels results and timers. Seeking waits for the single in-flight request and discards stale results; it does not spawn parallel requests in one playback state. Servers ignoring the requested absolute range are rejected instead of guessing time offsets. Empty forced-dialogue intervals are valid but do not prove actual subtitle output.

Fourteen local tests use a real HTTP server and original SRT parsing, player text rendering and stop/selection functions: actual visible text, automatic selection, continuous prefetch, cached/evicted/far seeks, bounded cache and request concurrency, empty intervals, failures, close/off cancellation, source changes, HD/external/full delegation, manual-off authority and rejection of ignored timestamp ranges. Installer packaging was checked against runtime.py; stacked installation, exact backup, source compilation, preserved local layout and repeat refusal passed. These tests validate the client implementation, not whether the user's server optimizes or honors these API parameters.

Receiver validation remains pending. Install the self-contained install.py using Python 3, restart the GUI, reopen the same 4K film without manual selection, and test a known foreign-dialogue scene. If it fails, read the last 12 lines of the safe segment diagnostic. The test does not require a sidecar or administrator, create subtitles, burn them into video, or guarantee all-film compatibility. Auto-update remains on 2026101703 until separately requested. Restore the printed `plugin.py.vor-ut-abschnitten-<timestamp>` backup and restart GUI to remove the test.
